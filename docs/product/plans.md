# Plans and routines

- Plans can contain routines, and routines may also exist without a plan. The Plans root does not support drag-and-drop or reordering; routine and plan interactions are opened from their visible option controls instead.
- A routine starts with an empty name, a workout type, an optional vertically centred note, optional named attributes with Forge icons whose values may be supplied later during a workout, and a reusable exercise/set structure. Its plan membership is not repeated as editor copy. Routine sets may carry an advisory reps, duration, or distance interval for the current session; these intervals are distinct from Next session targets and never create or propagate a user target when a routine or plan starts a workout. Routine and plan editors retain their normal outlined value boxes for this reusable structure, accept incomplete input while focused, render complete ranges with an en dash after blur, and can be cleared and entered again at any time. On a native iPhone build, interval entry uses Forge's in-app system-style numeric keyboard: the standard number-pad grid, system-matched Light/Dark colours, and a `−` key below `7` for a range. Expo Go and non-iOS builds retain a safe platform text-input fallback. The iPhone Rest Timer Live Activity uses the same stopwatch symbol as Live Workout across its lock-screen and Dynamic Island presentations.
- Users can create, visualize, edit, move, delete, and start routines. Starting a routine creates an independent active workout, so later edits do not alter an in-progress session; a workout started from a plan routine includes the plan name in its workout name.
- The Plans screen groups standalone routines and plans separately in shared, borderless Forge grouped-card surfaces. Routine rows use their workout-type icon, and swiping left on a routine or plan reveals its destructive Delete action. A plan's Add routine action is a compact 44 pt footer row with a divider, rather than an oversized standalone button. Empty routines show their type without a `0 exercises` count. The resting row remains fully opaque; when Delete is open, its destructive surface sits behind the retained trailing card curve. Press feedback is a brief restrained dimming of the touched control, never a persistent whole-card selection fill.
- Tapping a routine, whether standalone or inside a plan, opens the shared Forge action sheet. It orders Start, Edit, then Visualize; its workout-type icon remains the direct Start control. Plan actions are Add routine and Delete plan. Swiping left remains the destructive Delete path for both routine placements and plans.
- Plans and routines are local-only and persist through the Forge repository boundary backed by the local Forge SQLite database. Routine exercise/set structure is copied when a workout starts or when a historical workout is seeded from a routine, so later edits cannot alter the recorded session. A plan remains a container in the historical flow: users choose a specific routine before copying its editable snapshot.
- The Plans header action presents New workout, New routine, and New workout plan. On compact layouts it uses the shared action sheet; on wide layouts it uses an anchored menu directly below the Add control. The Dashboard creation action routes into Plans and opens this same presentation. New workout starts immediately. New routines, including routines added to a plan, open as local editor drafts and are persisted only by an explicit Save; Cancel or Back asks to discard unsaved changes. Routine attributes are user-defined names with optional values, such as Mood or Location. The editor's workout-type choice uses a dedicated modal picker, independent of the exercise list gesture surface. The routine editor reuses the Live Workout set editor: each exercise is a compact expandable row, with no overflow menu; its expanded content provides set editing, swipe-to-delete, and a dedicated long-press drag handle for reordering. A drag gives the held card a floating scale/shadow treatment and collapses every exercise row until it ends. Visualize is read-only: it has no add, delete, set-edit, or reorder controls, shows the type as a single horizontal summary without a disclosure arrow, and omits absent note and attribute rows. Its expanded exercise summaries use compact 44 pt set rows without intra-card dividers. Plan headers omit the routine count, use the standard 56 pt row height, and act as their options control; routine rows act as their action controls. Both use visible chevrons instead of overflow ellipses; the plan header is separated from its routines only by a thin inset divider.
- New standalone routines are created from that header action only; the Plans list does not expose a bottom creation button. Discarding a changed routine draft and deleting a routine use Forge's own centred confirmation card instead of a platform alert; its primary Keep editing action is visually distinct from the destructive choice, while the editor's header check remains the explicit Save action.
- Routine exercise sets use the selected exercise's tracking type. Structured measurements and optional min/max targets are copied into the independent workout with an immutable exercise snapshot; legacy weight/reps data remains readable.
- Recognised Forge catalogue exercises in routines and plans are canonicalised from their approved v4 or legacy identifiers when data is loaded or imported. Canonicalisation updates only catalogue identity, title and snapshot; set values, notes, completion, and exercise/set order remain unchanged. Custom or unrecognised exercises retain their saved name. Routine rep and duration ranges use the standard Apple punctuation keyboard; a comma is normalized to Forge's stored range separator while decimal weight input remains locale-aware.
- Exercise-library filtering uses the same staged local scope model as Live Workout: Workout type, Equipment, and true exercise Category. Workout-type drafts narrow the downstream Equipment and Category choices to compatible catalogue values. It never treats muscle metadata as Category; a fixed workout-type library context is represented by the screen title, while applied editable filters are communicated by the selected Filters trigger and its active-count badge.
