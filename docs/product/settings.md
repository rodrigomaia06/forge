# Settings

- Settings replaces the More destination in Forge's primary dock.
- Primary dock roots do not expose edge-swipe back to a previously visited destination; edge-swipe navigation is reserved for nested screens with an explicit Back path.
- Settings uses shared grouped-card treatment and a 20 pt screen inset. The root Settings destination is a fixed, non-scrollable overview and uses the same 56 pt single-line row height as Workout Types with distinct, unframed semantic icons. Nested settings retain the compact scale: primary row titles use the `cardTitle` role, single-line rows are 56 pt, and rows with supporting text are at least 68 pt. Primary-tab scroll bodies run behind the dock and reserve only its reachability inset; nested settings scroll to their own safe-area edge without a dock-sized lower band. Pickers, sheets, chips, inputs, colour choices, and other specialised controls retain their purpose-specific dimensions.
- Settings is a local-preferences hub. Exercises first lists visible workout types, then separate All and Custom destinations with semantic icons and counts. The browser groups exercises by movement: a single variation opens directly and still offers Add variation, while multiple variations disclose equipment groups and actionable variation rows. Custom exercises and variations use a Forge sheet that starts with the required name and essential equipment; an explicit Optional details control reveals Category, exercise group, type, and muscle metadata only when needed. Equipment and Category selectors have a shared query field that only narrows visible options—typing a matching name never chooses it. Focused selection subviews use the shared 44 pt grey circular chevron Back action and a short content transition, and the floating save action remains visible. Short selector subviews hug their content, while long choices stay in a capped scrolling sheet. Each variation detail shows its rest-time preference, sections with their type icons, movement category, and primary/secondary muscles. Rest Time replaces the exercise-detail content inside the same bottom sheet: it has a Back path, a Default action in its header, and five-second durations from 00:30 through 10:00 in a compact virtualized list positioned around the current value. Choosing a value persists it and returns to the detail; Back leaves it unchanged, while the sheet backdrop, downward gesture, and Android Back dismiss the sheet from the detail view. Forge exercises keep their catalogue metadata read-only but allow a locally persisted rest-time override; custom exercises and variations can be created, edited, deleted, and persist locally, including sections and muscle targets. Search includes names, aliases, movement groups, equipment, and primary or secondary muscle groups. All and type browsers offer staged multi-select Workout type, Equipment, and true taxonomy Category filters: the raised compact summary is fixed-height and non-scrollable, opens one full-row selector at a time, every choice list is searchable, draft selections cascade from type, Clear is a top-left shared destructive-outline action and resets only the draft, and the shared floating Apply action is disabled until that draft changes. A type-specific browser uses its screen title as the fixed scope. Custom reuses the search/list browser without filters. Workout types use compact visible/hidden lists and source signals (the Forge `rosette-discount-check` seal or custom pencil): Forge types expand inline to hide or show from future workout pickers, while custom types open the dedicated editor with named colors plus a visual custom-color picker that does not require text input. Creating a type starts an unsaved local draft; Save persists it and returns to the list, while Cancel or Back discards a changed draft only after confirmation. Existing workouts retain their saved type text.
- Equipment and Category queries only filter their corresponding option lists; they never implicitly select a matching result. Bodyweight is the default first-class equipment choice. Choosing Custom equipment opens a separate compact entry view, so the searchable equipment list never presents both a search field and an editable custom-value field. The root Filters summary is locally fixed-height and non-scrollable, with its rows anchored above the floating Apply treatment; only long choice lists scroll.
- Backup & Export and About mirror the local Forge information architecture. About shows the Forge app icon, version, privacy copy, and active Source code/GPL v3.0 links with Git and document icons. Backup, restore, import, export, and reset stay visibly unavailable until their data tools are implemented; Settings does not introduce authentication, remote logs, a database connection, or file integrations.
- General preferences persist locally in the Forge SQLite database and expose a compact Appearance row, metric/imperial default units, canonical bodyweight, Monday/Sunday first day of week, rest-timer defaults/alert preferences, and unfinished-workout reminder preferences. Its scrolling content shows the shared header edge when it passes behind the persistent header. Appearance opens the shared single-choice picker anchored to the bottom on mobile and a compact anchored menu on desktop. Default Rest Time and Remind After use the same single-choice picker rather than cycling values on row tap. Long, description-free single-choice duration lists are bounded to a compact visible window, virtualized, and initially positioned around the current value; short lists shrink to their contents. Appearance is resolved at runtime by the Forge theme provider: Light and Dark are explicit choices, while System follows the device color scheme; explicit choices also update native controls through `Appearance.setColorScheme`. Existing saved values remain valid. Dark and System are exposed with a beta note below the Appearance card until every visual group has passed the dark-theme audit. The first day of week immediately changes the Calendar; preferences do not convert recorded workout data. Keep rest timer running defaults on, preserving Forge’s red overdue state; an explicit user choice remains intact. When Rest timer is enabled, its sound preference controls Forge’s scheduled local end-of-rest notification on supported native builds. Selected Calendar days use a neutral theme ring so their day surface and workout-type markers remain visible; the dark ring has restrained contrast. Workout names always include their plan when the workout starts from a plan routine.
- Measurements is a Forge settings destination below Workout types and starts with no measures. Every numeric measure, including a user-named body-weight measure, is independent from General settings. The metric selector comes before that metric’s trend and dated history, so the current context is always established before analysis; switching metrics uses a short lateral content transition. Each measure has a user-chosen semantic icon and chart colour, unit, independent daily entries, a dated read-only history, and a 7/30/90-day trend whose x-axis preserves actual calendar gaps. Web uses the existing AsyncStorage persistence boundary rather than Expo SQLite's OPFS worker, so browser storage remains functional in secure and constrained contexts.
