# Settings

- Settings replaces the More destination in Forge's primary dock.
- Primary dock roots do not expose edge-swipe back to a previously visited destination; edge-swipe navigation is reserved for nested screens with an explicit Back path.
- Settings uses shared grouped-card treatment and a 20 pt screen inset. The root Settings destination is a fixed, non-scrollable overview and uses the same 56 pt single-line row height as Workout Types with distinct, unframed semantic icons. Nested settings retain the compact scale: primary row titles use the `cardTitle` role, single-line rows are 56 pt, and rows with supporting text are at least 68 pt. Their scroll bodies extend to the bottom screen edge; Exercise Library reserves the primary dock inset so its final category remains reachable. Pickers, sheets, chips, inputs, colour choices, and other specialised controls retain their purpose-specific dimensions.
- Settings is a local-preferences hub. Exercises first lists visible workout types, then separate All and Custom destinations with semantic icons and counts. The browser groups exercises by movement: a single variation opens directly and still offers Add variation, while multiple variations disclose equipment groups and actionable variation rows. Adding a variation inherits the movement category and presents its existing equipment as a single choice plus an explicit custom-equipment entry; section choices include their type icons and use neutral theme-aware selection styling. The New Custom Exercise category search commits a tapped result, collapses its suggestion list, and identifies the selected Forge or custom source; equipment choices show the same source signal. Each variation detail shows its rest-time preference, sections with their type icons, movement category, and primary/secondary muscles. Rest Time replaces the exercise-detail content inside the same bottom sheet: it has a Back path, a Default action in its header, and five-second durations from 00:30 through 10:00 in a compact virtualized list positioned around the current value. Choosing a value persists it and returns to the detail; Back leaves it unchanged, while the sheet backdrop, downward gesture, and Android Back dismiss the sheet from the detail view. Forge exercises keep their catalogue metadata read-only but allow a locally persisted rest-time override; custom exercises and variations can be created, edited, deleted, and persist locally, including sections and muscle targets. Search includes names, aliases, movement groups, equipment, and primary or secondary muscle groups. All and type browsers offer staged multi-select Workout type, Equipment, and true taxonomy Category filters in one sheet; the filters are compact wrapped selection chips that use horizontal space before vertical space, facet choices cascade from the selected type, and applied state is communicated only by the selected Filters trigger and its count. A type-specific browser uses its screen title as the fixed scope. Custom reuses the search/list browser without filters. Workout types use compact visible/hidden lists and source signals (the Forge `rosette-discount-check` seal or custom pencil): Forge types expand inline to hide or show from future workout pickers, while custom types open the dedicated editor with named colors plus a visual custom-color picker that does not require text input. Creating a type starts an unsaved local draft; Save persists it and returns to the list, while Cancel or Back discards a changed draft only after confirmation. Existing workouts retain their saved type text.
- Backup & Export and About mirror the local Forge information architecture. About shows the Forge app icon, version, privacy copy, and active Source code/GPL v3.0 links with Git and document icons. Backup, restore, import, export, and reset stay visibly unavailable until their data tools are implemented; Settings does not introduce authentication, remote logs, a database connection, or file integrations.
- General preferences persist locally in the Forge SQLite database and expose a compact Appearance row, metric/imperial default units, canonical bodyweight, Monday/Sunday first day of week, rest-timer defaults/alert preferences, and unfinished-workout reminder preferences. Its scrolling content shows the shared header edge when it passes behind the persistent header. Appearance opens the shared single-choice picker anchored to the bottom on mobile and a compact anchored menu on desktop. Default Rest Time and Remind After use the same single-choice picker rather than cycling values on row tap. Long, description-free single-choice duration lists are bounded to a compact visible window, virtualized, and initially positioned around the current value; short lists shrink to their contents. Appearance is resolved at runtime by the Forge theme provider: Light and Dark are explicit choices, while System follows the device color scheme; explicit choices also update native controls through `Appearance.setColorScheme`. Existing saved values remain valid. Dark and System are exposed with a beta note below the Appearance card until every visual group has passed the dark-theme audit. The first day of week immediately changes the Calendar; preferences do not convert recorded workout data or schedule notifications in this phase. Selected Calendar days use a neutral theme ring so their day surface and workout-type markers remain visible; the dark ring has restrained contrast. Workout names always include their plan when the workout starts from a plan routine.
- Daily measurements is a Forge settings destination for body weight and user-defined numeric measures. Body fat, waist, and resting-heart-rate are optional editable starting points; measures are never added without user action. Each measure has a unit, semantic icon, independent daily entries, and a 7/30/90-day trend whose x-axis preserves actual calendar gaps. Recording body weight updates the canonical default bodyweight too; metric and imperial entry/display preferences remain respected. Web uses the existing AsyncStorage persistence boundary rather than Expo SQLite's OPFS worker, so browser storage remains functional in secure and constrained contexts.
