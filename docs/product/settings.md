# Settings

- Settings replaces the More destination in Forge's primary dock.
- Primary dock roots do not expose edge-swipe back to a previously visited destination; edge-swipe navigation is reserved for nested screens with an explicit Back path.
- Settings is a local-preferences hub. Exercises first lists visible workout types, then separate All and Custom destinations with semantic icons and counts. The browser groups exercises by movement: a single variation opens directly, while multiple variations disclose equipment groups and actionable variation rows. Forge exercises remain immutable without explanatory read-only copy; custom exercises and variations can be created, edited, deleted, and persist locally. Search includes names, aliases, movement groups, equipment, and muscle groups. All and type browsers offer multi-select Type, Equipment, and Muscle filters in one sheet; facets combine together and selected values remain removable. Custom reuses the search/list browser without filters. Workout types use compact visible/hidden lists and source signals (Forge-provided seal or custom pencil): Forge types expand inline to hide or show from future workout pickers, while custom types open the dedicated editor with named colors plus a validated custom hex color. Existing workouts retain their saved type text.
- Backup & Export and About mirror the local Forge information architecture. About shows the Forge app icon, version, privacy copy, and active Source code/GPL v3.0 links with Git and document icons. Backup, restore, import, export, and reset stay visibly unavailable until their data tools are implemented; Settings does not introduce authentication, remote logs, a database connection, or file integrations.
- General preferences persist locally and expose a compact Appearance row, metric/imperial default units, canonical bodyweight, Monday/Sunday first day of week, rest-timer defaults/alert preferences, unfinished-workout reminder preferences, and workout-name formatting. Appearance opens a single-choice picker anchored to the bottom on mobile and a compact anchored menu on desktop. It is resolved at runtime by the Forge theme provider: Light and Dark are explicit choices, while System follows the device color scheme; explicit choices also update native controls through `Appearance.setColorScheme`. Existing saved values remain valid. Dark and System are exposed with a beta note below the Appearance card until every visual group has passed the dark-theme audit. The first day of week immediately changes the Calendar; preferences do not convert recorded workout data or schedule notifications in this phase.
