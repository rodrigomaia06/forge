# Settings

- Settings replaces the More destination in Forge's primary dock.
- Primary dock roots do not expose edge-swipe back to a previously visited destination; edge-swipe navigation is reserved for nested screens with an explicit Back path.
- Settings uses shared grouped-card treatment and a 20 pt screen inset. The root Settings destination is a fixed, non-scrollable overview and uses the same 56 pt single-line row height as Workout Types with distinct, unframed semantic icons. Nested settings retain the compact scale: primary row titles use the `cardTitle` role, single-line rows are 56 pt, and rows with supporting text are at least 68 pt. Primary-tab scroll bodies run behind the dock and reserve only its reachability inset; nested settings scroll to their own safe-area edge without a dock-sized lower band. Pickers, sheets, chips, inputs, colour choices, and other specialised controls retain their purpose-specific dimensions.
- Settings is a local-preferences hub. Exercises first lists visible workout types, then separate All and Custom destinations with semantic icons and counts. The browser groups exercises by movement: a single variation opens directly and still offers Add variation, while multiple variations disclose equipment groups and actionable variation rows within the same opaque card, separated from their trigger by a divider. Custom exercises and variations use a Forge sheet that starts with the required name and essential equipment; an explicit Optional details control reveals Category, exercise group, type, and muscle metadata only when needed. Equipment and Category selectors have a shared query field that only narrows visible options—typing a matching name never chooses it. Focused selection subviews use the shared 44 pt neutral elevated circular chevron Back action and a short content transition, and the floating save action remains visible. Short selector subviews hug their content, while long choices stay in a capped scrolling sheet. Each variation detail starts with a compact rest-time action, then groups essentials and training profile data into compact Forge cards rather than a long flat property list. A custom variation exposes its neutral Edit action in the header beside the title with the same muted circular surface as other header actions, while Delete remains a separately styled destructive action after its details. The Duration selector replaces exercise-detail content inside the same bottom sheet: it has a Back path, a selected Default action in the header's former Close position, and five-second durations from 00:30 through 10:00 in a compact virtualized list positioned around the current value. The selected duration receives Forge's success-green contextual treatment. Choosing a value persists it and returns to the detail; Back leaves it unchanged, while the sheet backdrop, downward gesture, and Android Back dismiss the sheet from the detail view. Forge exercises keep their catalogue metadata read-only but allow a locally persisted rest-time override; custom exercises and variations can be created, edited, deleted, and persist locally, including sections and muscle targets. Search includes names, aliases, movement groups, equipment, and primary or secondary muscle groups. All and type browsers offer staged multi-select Workout type, Equipment, and true taxonomy Category filters: the raised compact summary is fixed-height and non-scrollable, opens one full-row selector at a time, every choice list is searchable, draft selections cascade from type, Clear is a top-left shared destructive-outline action and resets only the draft, and the shared floating Apply action is disabled until that draft changes. A type-specific browser uses its screen title as the fixed scope. Custom reuses the search/list browser without filters. Workout types use compact visible/hidden lists and source signals (the Forge `rosette-discount-check` seal or custom pencil): included Forge types use the original distinct default swatches, while custom types open the dedicated editor with named colours plus a visual custom-colour picker that does not require text input and may deliberately reuse any included or custom colour. Forge types expand inline to hide or show from future workout pickers with a divider-delimited elevated subrow. Creating a type starts an unsaved local draft; Save persists it and returns to the list, while Cancel or Back discards a changed draft only after confirmation. Existing workouts retain their saved type text.
- Equipment and Category queries only filter their corresponding option lists; they never implicitly select a matching result. Bodyweight is the default first-class equipment choice. Custom exercises can select multiple equipment values in a searchable draft list with the shared floating Apply action; the first selected item is the primary hierarchy value while all selected values are retained for search, filters, detail and snapshots. The Add variation equipment list uses a taller bounded scroll region while Apply remains fixed, so the final choice never competes with confirmation. Choosing Custom equipment opens a separate compact entry view, so the searchable equipment list never presents both a search field and an editable custom-value field. The root Filters summary is locally fixed-height and non-scrollable, with its rows anchored above the floating Apply treatment; only long choice lists scroll.
- Backup & Export puts portable Data transfer first: JSON export begins with a selectable category list for workouts, plans/routines, custom exercises, workout types, and measurements; text uses the same selection but is only a read-only sharing summary. JSON import validates and normalizes the complete versioned shape, then opens the same selectable category list before an additive review and final confirmation; the review reports plans and routines separately and reports existing matching records as `on device`, never replacing current records. Existing IDs remain stable for repeat-safe merges; a hand-authored record without an ID receives a local UUID during import, so casual JSON authors do not need to invent identifiers. A matching plan retains its device fields and order while any new imported routines are appended inside it, so the hierarchy displayed in review is the hierarchy persisted after import. The resulting Forge decision card lists the categories actually added and states when matching records were retained. Native imports persist the normalized merged state in one SQLite transaction, so duplicate or cross-linked legacy IDs cannot leave a partial import; repository reads also normalize missing legacy workout child arrays before any screen consumes them. The information mark beside Import JSON is currently visual-only. Database backup below it serializes the complete Forge SQLite database, including WAL changes, to a `.sqlite` file. Restore validates the SQLite header, integrity and required Forge tables in memory before destructive confirmation, creates a local safety copy, then reloads the local providers. A distinct destructive Delete all app data action uses the shared Forge decision card before clearing all user-owned local Forge content, preferences, timer state and diagnostics while retaining only immutable bundled catalogue data needed for a fresh start. SQLite backup/restore is available only in iOS/Android builds; JSON transfer and local-data deletion remain available on web. Core Data backups from the previous Swift app are not Forge SQLite backups and must use JSON transfer instead. Logs is a local, capped diagnostic view: it records only allow-listed technical event kinds, never workout/exercise names, values, notes or identifiers, and supports manual export and confirmed clearing. The exported log omits internal event keys as well as user data. Settings does not introduce authentication, cloud sync, telemetry, or automatic log delivery. About shows the Forge app icon, version, privacy copy, and active Source code/GPL v3.0 links with Git and document icons.
- General preferences persist locally in the Forge SQLite database and expose a compact Appearance row, metric/imperial default units, canonical bodyweight, Monday/Sunday first day of week, rest-timer defaults/alert preferences, and unfinished-workout reminder preferences. Its scrolling content shows the shared header edge when it passes behind the persistent header. Appearance opens the shared single-choice picker anchored to the bottom on mobile and a compact anchored menu on desktop. Default Rest Time and Remind After use the same single-choice picker rather than cycling values on row tap. Long, description-free single-choice duration lists are bounded to a compact visible window, virtualized, and initially positioned around the current value; short lists shrink to their contents. Appearance is resolved at runtime by the Forge theme provider: Light and Dark are explicit choices, while System follows the device color scheme; explicit choices also update native controls through `Appearance.setColorScheme`. Existing saved values remain valid. Dark and System are exposed with a beta note below the Appearance card until every visual group has passed the dark-theme audit. The first day of week immediately changes the Calendar; preferences do not convert recorded workout data. Rest timer defaults are used when a completed set has no per-exercise rest override; each exercise's Rest Time override takes priority and is captured in the workout snapshot. Disabling Rest timer immediately stops its current timer and removes its system presentations. Keep rest timer running defaults on, preserving Forge’s red overdue state; an explicit user choice remains intact. When Rest timer is enabled, its sound preference selects an audible or silent Android notification channel and controls Forge’s scheduled local end-of-rest notification on supported native builds; Android uses Forge’s monochrome rest-clock notification icon. An unfinished-workout preference schedules one silent local reminder for an open workout and removes it as soon as that workout closes. Selected Calendar days use a neutral theme ring so their day surface and workout-type markers remain visible; the dark ring has restrained contrast. Workout names always include their plan when the workout starts from a plan routine.
- Measurements is a Forge settings destination below Workout types and starts with no measures. Every numeric measure, including a user-named body-weight measure, is independent from General settings. A compact horizontal metric selector comes before the active metric's summary, trend and dated history, so the current context is always established before analysis. The destination enters already settled; only a deliberate metric change within Measurements uses a short lateral content transition. The summary presents the latest value, its date, and the selected-period change. Each measure has a user-chosen semantic icon and chart colour, unit, independent daily entries, a month-grouped read-only history, and a 7/30/90-day trend whose x-axis preserves actual calendar gaps. Web uses the existing AsyncStorage persistence boundary rather than Expo SQLite's OPFS worker, so browser storage remains functional in secure and constrained contexts.
- JSON import preserves the source sequence of each accepted routine/workout's exercises and sets; if legacy JSON repeats an exercise or set ID within one list, Forge keeps the first occurrence at its original position.
