# History

- Completed workouts can be opened individually from the History list.
- History canonicalises recognised legacy catalogue exercise identity, names and snapshots during repository migration/import while preserving recorded sets, notes, completion and ordering. It never guesses a match for custom or unrecognised exercises.
- Sets in a completed workout expose their recorded type, comment, and next-time target from the compact set-number chip in the expanded exercise table; the read-only detail sheet remains available for deeper inspection and historical sets cannot be deleted there. Exercise notes use a chat indicator beside the exercise name without changing the card height. Historical exercise More actions provide read-only note viewing, previous sessions (excluding the current workout), and exercise information.
- A workout always has a note field, initially empty; empty notes are hidden. Context is represented only by user-defined named attributes with optional values and Forge icons; there are no fixed Location or Mood fields. Average rest remains a recorded workout metric: new sessions update it from the configured rest started after each completed set, while legacy records without captured rests remain unrecorded rather than being guessed.
- History groups completed workouts into relative periods with one continuous, low-contrast date timeline across period labels, a 44 pt workout-type icon, compact summary counts when exercises and sets exist, and a separate duration chip. The rail starts at the newest marker, ends at the oldest marker, and its row and between-period segments share one fixed centre line. Each between-period bridge softly fades toward its middle before returning to the in-week rail. Detailed cards are compact 70 pt rows; cards without an exercise/sets summary use a 60 pt height. A completed workout can be removed from its contextual options or by revealing its velocity-responsive swipe-to-delete action; deletion is immediate and persists. The complete outlined card moves during a swipe, keeping its trailing curve above the destructive surface revealed behind it.
- History supports a staged Forge filter sheet for one or more workout types plus the previous Forge date-range controls: All dates, a browsable calendar month, or explicit From/To dates. The root summary opens internal type/date views with Back, selections remain a draft until Apply, and clearing returns the full timeline.
- History shows its restrained elevated header edge only after content scrolls beneath the persistent header; nested detail/editor screens retain the same edge treatment.
- Workout detail begins with the shared neutral Forge workout-summary card. On phones it uses a fixed leading weekday/day/month date rail, then a small type marker, title with inline exercise/set counts, compact side-by-side Duration and Avg rest metrics, and optional note. The date rail and compact metric hierarchy are visually verified on iPhone Air and Samsung Galaxy S24. One user-defined attribute is shown directly as an icon/label/value row; two or more use a 44 pt info-icon disclosure identified by its attribute names and expand into the same icon/label/value grouped-row presentation as Live Workout. Attribute labels stay vertically centred beside values that wrap. Set metrics never appear in that attribute area. It is followed by individually expandable read-only exercise cards. Collapsed exercise cards keep the name and set count together in one compact row; expanded recorded sets retain the same stable Set, Previous, measurement, and completion grid as Live Workout. Historical missing prior values use `Not recorded`, and the completion check remains read-only.
- A completed workout can be edited from its contextual options. Editing operates on a local copy and requires an explicit Save; cancelling or leaving a modified editor discards only after confirmation. The editor begins with editable name and semantic-icon type fields, followed by Notes, an addable Attributes group, then date/start/end timing and exercises. Attribute rows retain an optional Forge icon, support edit and swipe-delete, and use the same focused editor as Live Workout. The type picker replaces the editor content with all visible types plus a retained hidden current type, and marks the selected row with Forge's success treatment. The editor uses the active-workout exercise controls, enlarged for the editing context, with the add-exercise action at the end of the list, but excludes live elapsed/rest timers. Date, start time, and end time open the shared Forge calendar or time-wheel picker. Changes remain local picker drafts until Done, with Back, Close, and dismissal discarding the picker draft; duration is calculated from the interval rather than manually entered. Save uses the workout type's semantic action color.
- History keeps set properties compact: set type, a next-session target, RPE, and a comment are represented inside the set-number chip (letter/colour, top-left marker, bottom-left effort, and comment marker). It does not add an annotation row beneath the recorded set. Missing read-only values use the explicit `Not recorded` label rather than a dash glyph.
- An empty Dashboard calendar date offers Add historical workout. A recorded workout in that selected day opens its corresponding read-only History detail, whose Back action returns to History. The mandatory source chooser composes and measures its choice card before the bottom-sheet entrance begins, so the complete choice travels with the sheet rather than appearing mid-motion. It opens either a blank unsaved draft or a routine chooser that first distinguishes standalone routines from plans, then requires a routine inside the selected plan. A routine-derived draft is an independent editable snapshot: it copies the routine name/type/note/exercise structure and attribute labels/icons with blank values; planned routines are named `Plan - Routine` and retain source IDs without displaying them. Later plan or routine edits and deletions do not affect a saved historical workout. The selected calendar date is already chosen, while start and end times remain required explicit choices. Saving appends the completed workout and returns to the saved date on Dashboard; cancelling creates no record.
- The workout detail remains read-only and does not provide a rest timer; it displays the recorded duration.
- Historical exercise More actions use the same read-only note and set-detail surfaces as live workout. Previous sessions use separated Forge cards with the shared set chips and indicators; each compact set’s right-side circular chip is its explicit properties control, leaving the card header to open the workout. Opening a session pushes its detail and popping returns to the originating active-workout sheet or History detail rather than resetting a tab root.
- Workout detail uses an icon-only Back action and a labeled More action; long workout names remain a single truncated centered line.
- Opening a completed workout preserves the History route beneath it: the iOS edge swipe and the labeled Back action both return to History, while a direct/restored detail route falls back to History. Selecting History from its nested detail/editor route returns to the History root.
- The existing workout-in-progress screen keeps its elapsed and rest timer behavior.
