## Findings

### 1. HIGH: RPE-only measurements could hide valid legacy weight and reps

**Fixed. R-26 / C-4.** Legacy sets can contain explicit RPE while weight and reps remain in their legacy columns. Using only the measurement array omitted valid working-set values. `src/domain/exercises/progress.ts` now supplements absent fields from the existing legacy conversion, while rejecting explicitly invalid or duplicated measurements. `tests/unit/exercise-progress.spec.ts` covers an RPE-only set and unchanged source values.

### 2. HIGH: Fractional repetitions were incorrectly treated as invalid

**Fixed. R-26 / C-4.** Forge explicitly accepts fractional repetitions. The first progress validation incorrectly required integers. Finite positive fractional reps now contribute to best reps, total reps and volume. The test covers 1.5 reps and 75 kg·reps at 50 kg. This preserves the accepted Live Workout requirement rather than adopting an inferred restriction.

### 3. HIGH: Previous sessions body could compete with sheet dragging

**Implementation/browser fixed; native verification required. R-03 / R-26.** Previous sessions now gives the compact scroll body a measured viewport and disables its drag-to-dismiss wrapper through an optional shared `ForgeSheetScrollView` property. Expanded history uses one bounded `FlatList`, without nested vertical scrollers. The sheet header retains dismissal ownership. Existing consumers keep the shared primitive's default behavior. The browser test verifies an overflowing three-session preview, inspection of set 6, Show more and absence of the body drag wrapper. Browser checks cannot prove native gesture arbitration.

### 4. HIGH: Early scroll events could overwrite the return position

**Fixed in browser checks. R-26 / C-4.** Review updates now merge against the latest state, and restoration waits for the list/sheet layout instead of accepting an early clamped offset. The expanded state and position survive set inspection, filtering review and workout drill-in/back. Tests scroll to Session 45, open its workout and return to that visible session. Library drill-in/back also retains History. Native restoration still needs device verification.

### 5. HIGH: New titles and selector outlines were not fully theme-aware

**Fixed. R-25 / R-34.** Progress/History/filtering titles now use `textPrimary`; labelled selector borders use `border`. No native default text or black outline is relied upon. Final Info, Progress, History and filtering screenshots cover both themes and both configured phone profiles.

### 6. HIGH: Labelled selections lacked reliable accessible and visual state

**Fixed. R-25 / R-32.** Both segmented modes expose checked state explicitly on web. The new labelled mode uses the existing `actionPrimary` / `onActionPrimary` palette for its selected pill, with 44 pt targets. Tests activate Progress and the chart by keyboard and verify checked selections, ranges and chart Previous/Next. Finite metric and exclusion choices reuse the shared selection list. The original icon-mode behavior stays intact.

### 7. HIGH: Light-mode failure and outline-save text missed normal-text contrast

**Fixed. R-25 / R-27.** Red error text measured 3.93:1 on the sheet, and the success outline label measured 4.07:1 on its fill. The error now uses primary text plus a warning icon; its explanation does not depend on color. Save/Retry uses the existing primary success variant (4.83:1 Light, 5.19:1 Dark). Failure retains Include and Retry persists that choice. Final failure captures verify the exact state in all four profile/theme combinations.

### 8. LOW: Constant series were positioned against a chart edge

**Fixed. R-31 / C-4.** Date-positioned chart geometry now centers a constant series, including a single-session history. Its pure layout test also verifies unequal date gaps. No fictitious progression, historical bodyweight or estimated 1RM is introduced. Existing undated chart consumers retain their previous implementation.

### 9. LOW: History had duplicate spacing and undersized action labels

**Fixed. R-03 / R-31 / C-5.** Removed the extra card margin, retaining one shared list gap. Session titles use Forge's card-title role; descriptive/status metadata uses the label role and filtering actions use the control-label role. Both-theme preview and expanded-list captures show full-width cards without overlap or clipped titles.

### 10. LOW: Removed history code left obsolete gesture comments

**Fixed. R-31 / antislop-code comment-value guidance.** Deleted comments and helpers tied to the removed history implementation. The retained warm-up comment describes its native layout constraint; warm-up working code is unchanged. The new restoration comment explains why early offsets can be clamped.

### 11. HIGH: Browser chart clicks did not resolve the intended point

**Fixed. R-26 / R-32.** Browser press events provide page coordinates rather than React Native's local `locationX`. The chart now translates page coordinates through its measured View, while native press events retain their local-coordinate path. Keyboard activation selects the first point and explicit Previous/Next controls navigate thereafter. Tests assert that keyboard activation and a subsequent pointer click change the selected session, rather than merely checking that the chart renders. The first final browser run exposed four failures here; after correction the four affected theme/profile flows pass on rerun.

### 12. LOW: Shortcut and library headers clipped or named the wrong tab

**Fixed. R-03 / R-31.** The Previous sessions shortcut now uses the shared Exercise info header and Close label, so switching to Info or Progress cannot leave a misleading Previous sessions title. Library exercise names can occupy two header lines through the existing shared header API. Final phone captures verify the previously clipped Galaxy S24 title. Set-inspection captures wait for the modal's opacity and translation to settle, and exclusion captures scroll the affected status into view.

## Skill recommendations and accepted Forge requirements

The Expo UI guidance recommends native `@expo/ui` controls by default. That conflicts with this task's explicit reuse of existing Forge components and prohibition on new dependencies. The implementation therefore uses Forge sheets, segmented controls, selectors, cards, set rows and chart entry point, with the existing SVG dependency for date-positioned session plotting. The antislop accent requirement is met by contextual Save and selection treatments; it does not justify adding colors, decoration or unrelated screen redesigns.
