# History

- Recorded set-number badges share the live-workout layout: the number or set-kind letter stays centered while RPE and target/comment dots fit around it without overlap.

- A failed saved-workout load is distinct from first use. Forge preserves unreadable active/archive records and offers retry plus the existing Backup & Export route before ordinary collection editing resumes. Database backup restore remains native-only.

- Completed workouts can be opened individually from the History list.
- History canonicalises recognised legacy catalogue exercise identity, names and snapshots during repository migration/import while preserving recorded sets, notes, completion and ordering. It never guesses a match for custom or unrecognised exercises.
- Sets in a completed workout expose their recorded type, comment, and next-time target from the compact set-number chip in the expanded exercise table; the read-only detail sheet remains available for deeper inspection and historical sets cannot be deleted there. Exercise notes use a chat indicator beside the exercise name without changing the card height. Historical exercise More actions provide read-only note viewing, previous sessions (excluding the current workout), and exercise information.
- A workout always has a note field, initially empty; empty notes are hidden. Context is represented only by user-defined named attributes with optional values and Forge icons; there are no fixed Location or Mood fields. Average rest remains a recorded workout metric: new sessions update it from the configured rest started after each completed set, while legacy records without captured rests remain unrecorded rather than being guessed.
- History groups completed workouts into relative periods with one continuous, low-contrast date timeline across period labels, a 44 pt workout-type icon, compact summary counts when exercises and sets exist, and a separate duration chip. The rail starts at the newest marker, ends at the oldest marker, and its row and between-period segments share one fixed centre line. Each between-period bridge softly fades toward its middle before returning to the in-week rail. Detailed cards are compact 70 pt rows; cards without an exercise/sets summary use a 60 pt height. A completed workout can be removed from its contextual options or by revealing its velocity-responsive swipe-to-delete action; deletion is immediate and persists. The complete outlined card moves during a swipe, keeping its trailing curve above the destructive surface revealed behind it.
- History supports a staged Forge filter sheet for one or more workout types plus the previous Forge date-range controls: All dates, a browsable calendar month, or explicit From/To dates. The root summary opens internal type/date views with Back, selections remain a draft until Apply, and clearing returns the full timeline.
- History and its nested detail/editor screens keep persistent headers unlined, including while content scrolls beneath them.
- Workout detail begins with the shared neutral Forge workout-summary card. On phones it uses a fixed leading weekday/day/month date rail whose day aligns with the workout identity title, then a small type marker, title with inline exercise/set counts, compact side-by-side Duration and Avg rest metrics, and optional note. The date rail and compact metric hierarchy are visually verified on iPhone Air and Samsung Galaxy S24. One user-defined attribute is shown directly as an icon/label/value row; two or more use a 44 pt info-icon disclosure identified by its attribute names and expand into the same icon/label/value grouped-row presentation as Live Workout. Attribute labels stay vertically centred beside values that wrap. Set metrics never appear in that attribute area. It is followed by individually expandable read-only exercise cards. Collapsed exercise cards keep the name and set count together in one compact row; expanded recorded sets retain the same stable Set, Previous, measurement, and completion grid as Live Workout. Historical missing prior values use `Not recorded`, and the completion check remains read-only.
- A completed workout can be edited from its contextual options. Editing operates on a local copy and requires an explicit Save; cancelling or leaving a modified editor discards only after confirmation. The editor begins with editable name and semantic-icon type fields, followed by Notes, an addable Attributes group, then date/start/end timing and exercises. Attribute rows retain an optional Forge icon, support edit and swipe-delete, and use the same focused editor as Live Workout. That compact editor aligns to the shared sheet inset, uses concise name/value fields with input placeholders instead of redundant field labels, and keeps the icon optically centred in its dedicated area above an unseparated 44 pt Change action. Its Save action sits immediately below the content rather than docked at the sheet edge. The type picker replaces the editor content with all visible types plus a retained hidden current type, and marks the selected row with Forge's success treatment. The editor uses the active-workout exercise controls, enlarged for the editing context, with the add-exercise action at the end of the list, but excludes live elapsed/rest timers. Date, start time, and end time open the shared Forge calendar or time-wheel picker. Changes remain local picker drafts until Done, with Back, Close, and dismissal discarding the picker draft; duration is calculated from the interval rather than manually entered. Save uses the workout type's semantic action color.
- History keeps set properties compact: set type, a next-session target, RPE, and a comment are represented inside the set-number chip (letter/colour, top-left marker, bottom-left effort, and comment marker). It does not add an annotation row beneath the recorded set. Missing read-only values use the explicit `Not recorded` label rather than a dash glyph.
- An empty Dashboard calendar date offers Add historical workout. A recorded workout in that selected day opens its corresponding read-only History detail, whose Back action returns to History. The mandatory source chooser composes and measures its choice card before the bottom-sheet entrance begins, so the complete choice travels with the sheet rather than appearing mid-motion. It opens either a blank unsaved draft or a routine chooser that first distinguishes standalone routines from plans, then requires a routine inside the selected plan. A routine-derived draft is an independent editable snapshot: it copies the routine name/type/note/exercise structure and attribute labels/icons with blank values; planned routines are named `Plan - Routine` and retain source IDs without displaying them. Later plan or routine edits and deletions do not affect a saved historical workout. The selected calendar date is already chosen, while start and end times remain required explicit choices. Saving appends the completed workout and returns to the saved date on Dashboard; cancelling creates no record.
- The workout detail remains read-only and does not provide a rest timer; it displays the recorded duration.
- Workout summaries omit Avg rest when no valid recorded average exists, without an empty rest column or a Not recorded placeholder. Recorded rest is never inferred from workout duration.
- Historical exercise More actions use the same read-only note and set-detail surfaces as live workout. Previous sessions use separated Forge cards with the shared read-only set-row layout: the properties chip leads the row, measurements use the same outlined tonal boxes as History and routine previews, and RPE, targets and comments stay within the chip rather than adding annotation rows. The card header opens the workout. Recorded History retains its read-only completion status and Previous column; Previous sessions and routine previews omit the completion column. Opening a session pushes its detail and popping returns to the Exercise Info History page with its position retained rather than resetting a tab root. Back from that page returns to the originating workout or catalogue.
- Workout detail uses an icon-only Back action and a labeled More action; long workout names remain a single truncated centered line.
- Opening a completed workout preserves the History route beneath it: the iOS edge swipe and the labeled Back action both return to History, while a direct/restored detail route falls back to History. Selecting History from its nested detail/editor route returns to the History root.
- The existing workout-in-progress screen keeps its elapsed and rest timer behavior.

- A finished session is saved exactly once even when submission is repeated. Unchecked and partially completed unilateral sets retain their current status. Recorded duration values display as mm:ss and persist in seconds. Exercise tracking overrides are part of the session contract and survive persistence and portable transfer; history matching distinguishes mode and repeated movement occurrence.

## Exercise history and progress

- Previous-session cards use a compact workout title/date header followed by completed recorded sets, without filtering controls. The full workout name remains accessible when its visible title is bounded. Presentation changes preserve preview scrolling, expanded virtualization and review-position restoration.

- Exercise Info and library exercise details open a dedicated full-screen page with shared Info, Progress and History tabs. Info is the default; Previous sessions opens History directly. The page shows the full exercise name in the top navigation header, one contextual Back control and no primary dock. Back preserves the originating workout or catalogue position. Quick exercise actions remain in a compact options sheet. Existing rest controls and custom-exercise actions remain available through shared Forge components.
- History matches canonical exercise identity and effective tracking mode. The existing normalized-name fallback is used only when the queried exercise has no identity. Different identities, variations and tracking modes remain separate. Repeated matching blocks are displayed within their original workout, and separate same-day workouts remain separate sessions.
- History previews three sessions in the dedicated page. Show more uses the available page viewport for a virtualized history without nested vertical scrolling or a drag-to-dismiss wrapper around its body. Set inspection and workout drill-in/back retain the originating tab, metric, range, expanded state and history position. Page scrolling and workout drill-in remain independent from the small set-inspection sheet's dismissal gestures.
- Progress uses completed workouts and completed working sets, excluding warm-ups, off-session blocks, invalid measurements and partially completed unilateral sets. Exercise Info History and Previous sessions show completed sets only; incomplete sets and partially completed unilateral sets are omitted, and sessions with no completed sets are omitted. Original recorded workouts remain unchanged. Supported fractional repetitions remain valid. One point per workout combines repeated matching blocks.
- Metrics follow the recorded tracking mode: heaviest absolute load, greatest added load or least assistance; weight/reps session volume; best-set and total repetitions; longest-set and total duration; total distance; and aggregate duration divided by aggregate distance for pace. Volume is the first selected graph metric when supported, labelled Volume; other tracking modes retain their applicable load, repetitions, distance or duration default. A chosen metric stays selected while navigating within the detail page and returning from workout drill-in. Calculations use canonical units and display uses current unit preferences. Historical bodyweight and estimated 1RM are not inferred.
- Progress offers 7d, 30d, 90d and All, defaulting to 90d. Points retain their actual session dates. The trend is a trailing median of up to five included sessions, available after three included sessions; its smooth, shape-preserving presentation never changes the computed values or invents intermediate sessions. Numerical increases are not automatically described as improvements.
- The detail page follows an open layout: Info uses aligned facts separated by subtle rules, with actionable rest and side settings grouped below; History uses the same compact session cards and shared read-only set rows as Previous sessions, without metric or filtering controls. Progress places the shared chart directly on the page without an enclosing card, with a compact metric control (including concise Weight, Added weight and Assistance labels), range choices, readable axis values and one selected-session date/value readout above the plot. Horizontal drag or tap selects actual sessions; accessible Previous/Next controls retain individual access to coincident-date points. Vertical gestures continue scrolling the page. Metric/range changes reset chart selection to the latest included session. Only a nonzero excluded count is shown; the explanatory algorithm paragraphs and Review history shortcut are omitted, while the History tab remains available.
- Automatic filtering is independent for each metric and starts after seven valid points. A seven-session neighbourhood supplies the neighbouring median and scaled median absolute deviation (MAD × 1.4826). A point is hidden only when its absolute deviation exceeds both 35% of the baseline median and 3.5 × scaled MAD. A zero baseline disables automatic filtering. Classification and smoothing precede range selection, so changing the display range cannot reclassify a session.
- Keep Info/Progress/History as the main tabs. Progress opens its date range from a compact chart-header menu alongside the metric control; it does not add a second segmented row. Metric and date range open anchored dropdown menus that retain the visible page, tabs and chart. The shared menus fit their option content instead of using a fixed wide panel, and use compact inset rounded rows, a quiet tonal selected fill, primary text and a checkmark within a softly rounded panel. Selecting a choice closes only the menu.
- Exercise Info History has no session-filtering controls or filtering status labels. Progress retains automatic filtering and respects existing stored overrides without exposing an editor in History. Exclusions never alter or delete recorded measurements.
- Override choices persist through the settings repository, keyed by exercise identity, effective tracking mode, metric and workout ID. Invalid stored choices are discarded on load. Portable `.forge` exports with workouts and complete native database backups preserve these choices; older backups default to none. Portable merges retain current local choices and only accept imported choices for retained workout IDs. Exercise settings are always editable, including when opened from recorded workouts. Rest and between-sides duration use the shared fixed-height duration wheel, with its full viewport visible above the sheet footer; rest and leading-side changes update exercise preferences without rewriting recorded sets.
