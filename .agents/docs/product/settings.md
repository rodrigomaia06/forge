# Settings

- Catalogue variation names use a constrained title column with up to two visible lines and reserved trailing space for badges and disclosure controls. The full name remains accessible; long titles never push adjacent controls outside the row.

- Import from another app presents each supported app as a joined, tappable source row with its outline brand icon and export instructions. Selecting a source opens its file picker; validated headers must agree with that choice. There is no separate generic Choose CSV action. The Strive row ends its export instructions at “.sqlite backup.” Browser builds disable that row and explain native availability inside it; its title and icon retain the same colors as the other sources.

- Strive SQLite backups with compatible required tables and fields, regardless of database version, import recorded history and active templates as standalone routines, without creating a plan. Deleted routines, plan schedules, progression-rule tables, global/pinned exercise notes, measurements, preferences, photos and precomputed personal records are excluded. An isolated cache copy is read without restoring it over Forge. Workouts and routines share exercise matching, selection, conflict review and one native atomic save with custom exercises and mappings. Stable source IDs distinguish history from templates and preserve same-day workouts; repeats are skipped and changed records default to Keep existing. Replacing a routine preserves its current position and plan membership if the user moved it after importing. Unix-seconds dates, exercise/set ordering, notes, supersets, weight units, effort, supported set types, blank prescribed sets and routine rep ranges are preserved; ranges remain planned hints when starting a routine. Strive durations and duration ranges use seconds without prompting. Metric distances use kilometres and imperial distances use miles from the source unit flag. Unknown optional columns, unsupported set types and automation fields are ignored; a missing unit flag omits that measurement instead of guessing. Invalid records are excluded as whole workouts or routines with acknowledgment. Only recognized source fields are retained, with ignored-field limitations disclosed. Browser builds retain CSV imports; Strive database imports require iOS or Android.

- A measurement editor acknowledges Save only after local persistence succeeds. A failed write keeps the value and date draft available, reports the failure in a compact tonal card with a status icon, clear title and retry guidance, and allows retry through the existing Save action; the displayed saved reading remains the last durable value.

- Catalogue curation canonicalizes audited punctuation/singular/plural source aliases such as Pull-Up/Pullups into one Forge identity and maps only those known legacy identifiers; unknown custom exercises remain untouched.

- Settings remains the destination in Forge's primary dock; its screen heading reads “More”. This label change does not move or replace the dock destination.
- Logs is hidden by default, including for existing preferences without an explicit opt-in. Three presses on the Forge logo in About toggle access on or off and show a saved-state acknowledgement. The choice persists across launches. Disabling access hides the Logs destination without deleting diagnostics or changing event collection.
- More groups Backup & Export and About into one two-row card. Enabled Logs uses a separate card.
- Primary dock roots do not expose edge-swipe back to a previously visited destination; edge-swipe navigation is reserved for nested screens with an explicit Back path.
- Settings uses shared grouped-card treatment and a 20 pt screen inset. The root Settings destination is a fixed, non-scrollable overview and uses the same 56 pt single-line row height as Workout Types with distinct, unframed semantic icons. Nested settings retain the compact scale: primary row titles use the `cardTitle` role, single-line rows are 56 pt, and rows with supporting text are at least 68 pt. Primary-tab scroll bodies run behind the dock and reserve only its reachability inset; nested settings scroll to their own safe-area edge without a dock-sized lower band. Pickers, sheets, chips, inputs, colour choices, and other specialised controls retain their purpose-specific dimensions.
- Settings is a local-preferences hub. Exercises first lists visible workout types, then separate All and Custom destinations with semantic icons and counts. The browser virtualizes movement families and lazily renders expanded variants. Families with controlled facets expose multi-select modifier rows; a load mode plus one movement detail resolves automatically, while two independent movement details or competing values open an output chooser. Assistance is an exclusive load mode with an optional explicit Machine/Band method, never a weighted-assisted result. Unstructured source-specific variants remain named standalone choices. The browser groups exercises by movement: a single variation opens directly and still offers Add variation, while multiple variations disclose equipment groups and actionable variation rows within the same opaque card, separated from their trigger by a divider. Custom exercises and variations use a Forge sheet that starts with the required name and essential equipment; an explicit Optional details control reveals Category, exercise group, type, and muscle metadata only when needed. Equipment and Category selectors have a shared query field that only narrows visible options—typing a matching name never chooses it. Focused selection subviews use the shared 44 pt neutral elevated circular chevron Back action and a short content transition, and the floating save action remains visible. Short selector subviews hug their content, while long choices stay in a capped scrolling sheet. Each variation detail starts with a compact rest-time action, then groups essentials and training profile data into compact Forge cards rather than a long flat property list. A custom variation exposes its neutral Edit action in the header beside the title with the same muted circular surface as other header actions, while Delete remains a separately styled destructive action after its details. The Duration selector replaces exercise-detail content inside the same bottom sheet: it has a Back path, a selected Default action in the header's former Close position, and five-second durations from 00:30 through 10:00 in a compact virtualized list positioned around the current value. The selected duration receives Forge's success-green contextual treatment. Choosing a value persists it and returns to the detail; Back leaves it unchanged, while the sheet backdrop, downward gesture, and Android Back dismiss the sheet from the detail view. Forge exercises keep their catalogue metadata read-only but allow a locally persisted rest-time override; custom exercises and variations can be created, edited, deleted, and persist locally, including sections, muscle targets, and a unilateral flag. Unilateral movements show the shared unilateral badge on their library rows, and their detail exposes the same Unilateral section — between-sides rest and leading-side options — as the live-workout exercise info so browsing and logging present unilateral exercises identically. Search includes names, aliases, movement groups, variation facets, equipment, and primary or secondary muscle groups. All and type browsers offer staged multi-select Workout type, Equipment, and true taxonomy Category filters: the raised compact summary is fixed-height and non-scrollable, opens one full-row selector at a time, every choice list is searchable, draft selections cascade from type, Clear is a top-left shared destructive-outline action and resets only the draft, and the shared floating Apply action is disabled until that draft changes. A type-specific browser uses its screen title as the fixed scope. Custom reuses the search/list browser without filters. Workout types use compact Included, Custom, and Hidden grouped lists with names alphabetized within each group, omitting empty groups, with current type icons tinted by their chosen colour and source signals (the Forge `rosette-discount-check` seal or custom pencil). Every type opens the shared editor: included names stay read-only, while included and custom colours are editable through a compact Color row and Forge sheet with integrated preset swatches and a custom-colour editor. Included types also offer Default color to restore their original Forge swatch. Explicit colour customization survives legacy-default upgrades, reloads, and portable normalization; colours may deliberately reuse any included or custom colour. Current type colours apply throughout the app, including existing History and Calendar presentation, without rewriting recorded training. The editor exposes Available in workout pickers for visibility; existing edits persist immediately. Creating a type starts an unsaved local draft; Save persists it and returns to the list, while Cancel or Back discards a changed draft only after confirmation. Existing workouts retain their saved type text.
- Included and custom workout types offer a shared Icon selector with Forge’s curated glyphs in a circular visual grid and a timer-style Default icon header action. Grid choices have accessible names and a neutral selection ring while keeping the glyph visible. The identity row previews the current icon and colour; Included, Custom and Hidden list rows use that same coloured icon instead of a dot. The curated selector includes strength, cardio, mobility and sport glyphs, with readable names matching their actual artwork. Existing icon edits persist immediately; new-type icon choices remain drafts until Save and count as changes for discard confirmation. Current icon preferences apply to saved workout presentation, History, Plans, import review and the live-workout dock without rewriting workouts. Optional icon overrides survive local persistence and portable normalization; missing or unsupported overrides use the default glyph. Existing-type editors also show Used in counts for saved, completed workouts and routines across standalone routines and all plans. A nonzero count opens a filtered, individually virtualized list that links to workout details or read-only routines and preserves the Back path to the type editor; zero counts are disabled. Matching uses the saved type name or identity, ignoring case and surrounding whitespace.
- Custom workout-type colours use a saturation/brightness panel, hue slider and old/new colour preview inside the existing Forge sheet. Picker gestures and keyboard/accessibility adjustment preview an opaque colour locally; Apply color commits it to the existing type or new-type draft. Back, Close, backdrop and gesture dismissal discard unconfirmed colour changes. The Color row opens one interactive picker with preset swatches below its hue slider; it does not expose a separate preset screen or a Color picker list option. A preset updates the local preview, panel and hue selection, and requires Apply color to commit just like a custom colour. Color and icon resets use the timer picker’s neutral Default header pill. Built-in Default color immediately restores the original swatch and clears customization; Default icon clears the override. Compact icon and colour selectors only scroll when their contents overflow.
- Equipment and Category queries only filter their corresponding option lists; they never implicitly select a matching result. Bodyweight is the default first-class equipment choice. Custom exercises can select multiple equipment values in a searchable draft list with the shared floating Apply action; the first selected item is the primary hierarchy value while all selected values are retained for search, filters, detail and snapshots. The Add variation equipment list uses a taller bounded scroll region while Apply remains fixed, so the final choice never competes with confirmation. Choosing Custom equipment opens a separate compact entry view, so the searchable equipment list never presents both a search field and an editable custom-value field. The root Filters summary is locally fixed-height and non-scrollable, with its rows anchored above the floating Apply treatment; only long choice lists scroll.
- Backup & Export puts portable Data transfer first: JSON export begins with a selectable category list for workouts, plans/routines, custom exercises, workout types, and measurements; text uses the same selection but is only a read-only sharing summary. JSON import validates and normalizes the complete versioned shape, then opens the same selectable category list before an additive review and final confirmation; the review reports plans and routines separately and reports existing matching records as `on device`, never replacing current records. Existing IDs remain stable for repeat-safe merges; a hand-authored record without an ID receives a local UUID during import, so casual JSON authors do not need to invent identifiers. A matching plan retains its device fields and order while any new imported routines are appended inside it, so the hierarchy displayed in review is the hierarchy persisted after import. The resulting Forge decision card lists the categories actually added and states when matching records were retained. A shared single item skips the category grid for a focused in-sheet review of only what it carries; a content-identical re-import is skipped rather than duplicated. When a shared item would update one already on this device (same name, different content) — the only problem case — its resolution moves to a dedicated full screen that presents the field- and child-level changes and an explicit Update (replace in place) / Keep both (numbered copy) / Skip decision, while every problem-free import stays in the in-sheet review and its popup confirmation. Native imports persist the normalized merged state in one SQLite transaction, so duplicate or cross-linked legacy IDs cannot leave a partial import; repository reads also normalize missing legacy workout child arrays before any screen consumes them. The information mark beside Import JSON is currently visual-only. Database backup below it serializes the complete Forge SQLite database, including WAL changes, to a `.sqlite` file. Restore validates the SQLite header, integrity and required Forge tables in an isolated cache-backed candidate before destructive confirmation, creates a local safety copy, then reloads the local providers. Backup and restore confirmation, success, and failure use the shared Forge decision card; failures never expose native SQLite implementation text. A distinct destructive Delete all app data action uses the shared Forge decision card before clearing all user-owned local Forge content, preferences, timer state and diagnostics while retaining only immutable bundled catalogue data needed for a fresh start; its completion acknowledgement is also a Forge decision card rather than a platform alert. SQLite backup/restore is available only in iOS/Android builds; JSON transfer and local-data deletion remain available on web. Core Data backups from the previous Swift app are not Forge SQLite backups and must use JSON transfer instead. Logs is a local, capped diagnostic view: it records only allow-listed technical event kinds, never workout/exercise names, values, notes or identifiers, and supports manual export and confirmed clearing. The exported log omits internal event keys as well as user data. Settings does not introduce authentication, cloud sync, telemetry, or automatic log delivery. About shows the Forge app icon, version, privacy copy, and active Source code/GPL v3.0 links with Git and document icons.
- General preferences persist locally in the Forge SQLite database and expose a compact Appearance row, metric/imperial default units, canonical bodyweight, Monday/Sunday first day of week, rest-timer defaults/alert preferences, and unfinished-workout reminder preferences. Its scrolling content shows the shared header edge when it passes behind the persistent header. Appearance opens the shared single-choice picker anchored to the bottom on mobile and a compact anchored menu on desktop. Default Rest Time and Remind After use the same single-choice picker rather than cycling values on row tap. Long, description-free single-choice duration lists are bounded to a compact visible window, virtualized, and initially positioned around the current value; short lists shrink to their contents. Appearance is resolved at runtime by the Forge theme provider: Light and Dark are explicit choices, while System follows the device color scheme; explicit choices also update native controls through `Appearance.setColorScheme`. Existing saved values remain valid. Dark and System are exposed with a beta note below the Appearance card until every visual group has passed the dark-theme audit. The first day of week immediately changes the Calendar; preferences do not convert recorded workout data. Rest timer defaults are used when a completed set has no per-exercise rest override; each exercise's Rest Time override takes priority and is captured in the workout snapshot. Unilateral exercises additionally use a shorter between-sides rest after the first side, with its own General default and per-exercise override; a Skip rest between sides preference suppresses only that between-sides rest while the normal between-set rest still runs. Disabling Rest timer immediately stops its current timer and removes its system presentations. Keep rest timer running defaults on, preserving Forge’s red overdue state; an explicit user choice remains intact. When Rest timer is enabled, its sound preference selects an audible or silent Android notification channel and controls Forge’s scheduled local end-of-rest notification on supported native builds; Android uses Forge’s monochrome rest-clock notification icon. An unfinished-workout preference schedules one silent local reminder for an open workout and removes it as soon as that workout closes. Selected Calendar days use a neutral theme ring so their day surface and workout-type markers remain visible; the dark ring has restrained contrast. Workout names always include their plan when the workout starts from a plan routine.
- Measurements is a Forge settings destination below Workout types and starts with no measures. Every numeric measure, including a user-named body-weight measure, is independent from General settings. A compact horizontal metric selector comes before the active metric's summary, trend and dated history, so the current context is always established before analysis. The destination enters already settled; only a deliberate metric change within Measurements uses a short lateral content transition. The summary presents the latest value, its date, and the selected-period change. Each measure has a user-chosen semantic icon and chart colour, unit, independent daily entries, a month-grouped read-only history, and a 7/30/90-day trend whose x-axis preserves actual calendar gaps. Web uses the existing AsyncStorage persistence boundary rather than Expo SQLite's OPFS worker, so browser storage remains functional in secure and constrained contexts.
- JSON import preserves the source sequence of each accepted routine/workout's exercises and sets; if legacy JSON repeats an exercise or set ID within one list, Forge keeps the first occurrence at its original position. Legacy snapshots that incorrectly label an externally loaded exercise as reps-only are safely restored to Weight + reps, while bodyweight and current/custom tracking choices remain unchanged.
- JSON import canonicalises only exercises with an approved v3 id, audited Forge legacy id, or unambiguous confirmed alias. It replaces their catalogue id, displayed name and snapshot while preserving user-entered sets, notes, completion, and source order; unknown/custom records retain their original identity and name.

- Import from another app accepts local workout-history CSV exports from Hevy, Strong, FitNotes Android and FitNotes iOS. Forge detects supported formats from validated headers and supports quoted fields, comma/semicolon separators and supported locale variants. Recognizable source-app logos, redrawn with Tabler-style rounded outlines and Forge theme colors, accompany the export instructions and detected-source label. It asks for ambiguous date order or missing measurement units before review; timestamps without a timezone use the device's local timezone. FitNotes files without session identifiers are grouped by date, with that reconstruction limitation visible in review. Imports retain session/exercise/set order, notes, supported measurements, effort, set types and supersets; source fields without a Forge equivalent remain in import metadata. Imported measurements use Forge's canonical units.
- CSV imports preserve the existing History rows and set-details presentation; they do not add separate imported-measurement summaries or sections there. Measurements beyond the displayed tracking fields remain preserved in the saved data and portable backups.
- CSV exercise review prioritizes exercises that require a choice and uses one continuous grouped list with row dividers, without repeated match-status labels. Other exercises remain available through Show all exercises while choices are outstanding. Library selection reuses the app's exercise picker with search, filters and variations, restricted to one result. Sheet titles stay short; full source exercise names wrap in their body. Library and custom actions reuse Forge's existing layers and stars icons. Custom source exercises and composed variations remain drafts until import confirmation; canceling creates no exercises or mappings.
- The complete CSV import flow reuses Forge controls and continuous grouped rows, including export instructions, validation, workout selection, conflict details, confirmation and results. Status icons accompany readable labels for required choices, changed workouts, duplicates, custom exercises and saved results; colour alone never conveys status. File checks, exercises and workouts have a visible progress label. Required source details and validation decisions precede secondary import notes. Confirmation and results show relevant nonzero counts in separate labelled rows, with a quieter return-to-review action and the shared success-outline final confirmation. Long summaries scroll while their actions stay reachable. Titles remain short and row text wraps rather than being truncated.
- CSV review reports validation problems by source row and field. Invalid rows exclude their complete session rather than creating partial workouts; importing the remaining valid workouts requires explicit acknowledgment. Exercise resolution automatically accepts only unique catalogue names or approved aliases after controlled naming normalization, and valid previously confirmed mappings. Uncertain matches require choosing a library exercise or preserving the source exercise as custom, without inventing equipment or muscle classifications. Confirmed mappings are remembered locally and can be changed during subsequent review; missing or archived targets are revalidated.
- CSV session matching uses import provenance and content rather than occupied dates, preserving multiple sessions on the same day. Identical reimports are skipped even when an imported workout has since been edited locally. Changed sessions require an explicit Keep existing, Replace or Keep both choice, defaulting to Keep existing; ambiguous identities cannot replace a record. The final confirmation states additions, replacements, duplicates and exclusions, and the result includes custom-exercise counts. Provenance and source metadata survive portable `.forge` backup/restore; locally remembered mappings are included in full native database backups and cleared by Delete all app data.
- CSV imports save selected sessions and their required custom exercises and mappings. Explicitly changed exercise matches can also be confirmed and saved with any required custom targets when all sessions are duplicates or unselected; existing workouts stay unchanged in that case. Settings, plans, unrelated sessions and active workouts remain intact. The repository rechecks reviewed conflicts before saving. Native persistence uses one serialized SQLite transaction; browser multi-key writes use a recovery journal that restores the previous data after failures or interruption. A failed save keeps the review draft and selections for retry. Back navigation within review retains the draft; canceling abandons it without persistence. Large histories use virtualized review lists and cooperative parsing. CSV imports do not add API/cloud access, CSV export, generic column mapping or new exercise-library behavior.

- The muscle heatmap uses legible neutral anatomy and a consistent low-to-high intensity ramp in Light and Dark. Its figures and legend share the same colours in dashboard and detail views, and front/back figures fit their available columns without overlap.

- Native `.forge` exports use a dedicated Forge document type and MIME identity while retaining the portable JSON payload. An installed native build registers Forge as the owning `.forge` handler for Files and compatible attachment apps, and routes cold and warm file opens into the existing import review without adding data before confirmation. iOS imports a sandbox-local copy rather than editing the source document in place. Android accepts named `.forge` URIs with or without a provider MIME type, plus opaque provider URIs carrying the Forge MIME type or the previous JSON MIME type; content validation remains mandatory. Registration changes require a rebuilt installed app, not Expo Go or a web update. Respect the user’s chosen OS default application; Files’ Open With or Always Open With can select Forge when another handler is already preferred.

- `.forge` documents use a folded-page icon containing the existing Forge logo. Native iOS builds bundle document-icon resources for system file presentation; Android exposes the same artwork for Forge’s file-opening chooser entry. External file managers and providers control their own file-list icons, so Android downloads do not have a guaranteed custom thumbnail.

- Exercise matching across Hevy, Strong, FitNotes Android/iOS and Strive recognizes common singular/plural variants, equipment abbreviations, source equipment parentheses and word-order differences, plus precise movement synonyms. Full movement and equipment tokens must agree; a unique catalogue name takes priority over broad aliases. Confirmed local mappings remain authoritative while their target is available. Ambiguous equipment or variation matches remain reviewable and never silently select a different movement.

- Library exercise details share the workout Exercise Info tabs: Info is the default, with Progress and History beside it. Rest controls and custom-exercise actions stay available; opening a historical workout and returning restores the detail's review state. Exercise progress uses current unit preferences and the calculation/filtering contract in History requirements. Per-exercise, tracking-mode, metric and workout exclusion overrides persist through the settings repository, are validated on load and travel with workouts in portable `.forge` backups. Complete native database backups also retain them. Failed override saves retain the selection for retry; older backups have no overrides.
