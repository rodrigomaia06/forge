# Plans and routines

- A failed saved-library load is distinct from an empty library. Forge preserves unreadable records, offers an explicit retry and the existing Backup & Export recovery route, and keeps ordinary collection editing unavailable until hydration succeeds.

- Plans can contain routines, and routines may also exist without a plan. In edit mode, every standalone or plan routine has the same direct drag-handle reorder interaction as a Dashboard tile. A routine can be reordered within its current group, and its resulting order persists without removing any routine. Moving a routine between standalone Routines and a plan uses the routine's Move to action. Plans use their visible up/down controls for ordering.
- A routine starts with an empty name, a workout type, an optional vertically centred note, optional named attributes with Forge icons whose values may be supplied later during a workout, and a reusable exercise/set structure. Its plan membership is not repeated as editor copy. Routine sets may carry an advisory reps, duration, or distance interval for the current session; these intervals are distinct from Next session targets and never create or propagate a user target when a routine or plan starts a workout. Routine and plan editors retain their normal outlined value boxes for this reusable structure, accept incomplete input while focused, render complete ranges with an en dash after blur, and can be cleared and entered again at any time. Native interval entry uses the dedicated range keypad described below. The iPhone Rest Timer Live Activity uses the same stopwatch symbol as Live Workout across its lock-screen and Dynamic Island presentations.
- Users can create, visualize, edit, move, delete, and start routines. Starting a routine creates an independent active workout, so later edits do not alter an in-progress session; a workout started from a plan routine includes the plan name in its workout name.
- Visualize routine uses a three-dot options action in the header. Its menu offers Edit routine, Share routine and Delete routine; editing opens the existing editor after the menu closes.
- The Plans screen groups standalone routines and plans separately in shared, borderless Forge grouped-card surfaces. Routine rows use their workout-type icon, and swiping left on a routine or plan reveals its destructive Delete action; a routine uses a 56 pt rounded inset Delete target. A plan's Add routine action is a compact 44 pt footer row with a divider, rather than an oversized standalone button. Empty routines show their type without a `0 exercises` count. The resting row remains fully opaque; when Delete is open, its destructive surface sits behind the retained trailing card curve. Press feedback is a brief tint across the touched control, never a persistent whole-card selection fill.
- Tapping a routine, whether standalone or inside a plan, opens the shared Forge action sheet in both modes. Outside edit mode it is the quick-use set — Start, Visualize, Edit — and the workout-type icon remains a direct Start control. In edit mode it is the modify set — Move to… (when a destination exists), Edit, Duplicate, Delete — where Delete routes through the shared confirmation. Plan actions are Add routine and Delete plan. Swiping left remains a destructive Delete path for both routine placements and plans.
- Plans and routines are local-only and persist through the Forge repository boundary backed by the local Forge SQLite database. Routine exercise/set structure is copied when a workout starts or when a historical workout is seeded from a routine, so later edits cannot alter the recorded session. A plan remains a container in the historical flow: users choose a specific routine before copying its editable snapshot.
- The Plans header action presents New workout, New routine, and New workout plan. On compact layouts it uses the shared action sheet; on wide layouts it uses an anchored menu directly below the Add control. The Dashboard creation action routes into Plans and opens this same presentation. New workout starts immediately. New routines, including routines added to a plan, open as local editor drafts and are persisted only by an explicit Save; Cancel or Back asks to discard unsaved changes. Routine attributes are user-defined names with optional values, such as Mood or Location. The editor's workout-type choice uses a dedicated modal picker, independent of the exercise list gesture surface. The routine editor reuses the Live Workout set editor: each exercise is a compact expandable row, with no overflow menu; its expanded content provides set editing, swipe-to-delete, and a dedicated long-press drag handle for reordering. A drag gives the held card a floating scale/shadow treatment and collapses every exercise row until it ends. Visualize is read-only: it has no add, delete, set-edit, or reorder controls, shows the type as a single horizontal summary without a disclosure arrow, and omits absent note and attribute rows. Its expanded exercise summaries use compact 44 pt set rows without intra-card dividers. Plan headers omit the routine count, use the standard 56 pt row height, and act as their options control; routine rows act as their action controls. Routine-name actions tint their full action area; routine choices use the same treatment. Both use visible chevrons instead of overflow ellipses; the plan header is separated from its routines only by a thin inset divider.
- New standalone routines are created from that header action only; the Plans list does not expose a bottom creation button. Discarding a changed routine draft and deleting a routine or plan use Forge's own centred confirmation card instead of a platform alert; the confirmation is required for both the swipe Delete and the options-sheet Delete, its primary Keep editing/Cancel action is visually distinct from the destructive choice, and the editor's header check remains the explicit Save action. Deleting a plan removes only the plan; its routines are kept and moved to standalone Routines.
- Routine exercise sets use the selected exercise's tracking type. Structured measurements and optional min/max targets are copied into the independent workout with an immutable exercise snapshot; legacy weight/reps data remains readable.
- Recognised Forge catalogue exercises in routines and plans are canonicalised from their approved v4 or legacy identifiers when data is loaded or imported. Canonicalisation updates only catalogue identity, title and snapshot; set values, notes, completion, and exercise/set order remain unchanged. Custom or unrecognised exercises retain their saved name. Native iOS and Android range fields use Forge's dedicated in-app numeric keypad with digits, a range separator, repeating backspace and dismissal. UIKit and Kotlin own native text entry and keypad presentation; TypeScript owns range parsing and normalization. Pasted and hardware-entered notation remains supported. Web and runtimes without the module retain the platform text-input fallback. Logged decimal measurements and clock fields retain their appropriate system keyboards. The native keypad reports its occupied bounds to shared sheet avoidance and focused-row lifting; Android Back dismisses it before leaving the sheet or screen.
- Exercise-library filtering uses the same staged local scope model as Live Workout: Workout type, Equipment, and true exercise Category. Workout-type drafts narrow the downstream Equipment and Category choices to compatible catalogue values. It never treats muscle metadata as Category; a fixed workout-type library context is represented by the screen title, while applied editable filters are communicated by the selected Filters trigger and its active-count badge.

- Routine exercise editing includes compatible Tracking choices. Explicit tracking overrides persist across starts, canonicalization, imports/exports and copying; catalogue defaults remain unchanged. Selected fields are all required, and duration intervals retain their seconds-based input.
- The workout finish sheet offers Keep original routine, Update existing routine and Save as new routine when reusable structure changes. Selecting Save as new expands the routine choices card directly below that option with an inset group containing the name and destination; selecting another outcome collapses those fields while retaining the draft name. Saving as new preserves the original, requires a nonblank inline name initially <original name> (new), and uses the original plan if it still exists, otherwise standalone Routines. A deleted originating routine cannot be updated.
- Updating or creating a routine from a session retains only reusable exercise order, effective tracking, set structure and compatible routine intervals. Session measurements, completion, RPE, comments, next-session targets and session-only warm-ups are excluded. Existing reusable notes remain; new routines receive fresh routine, exercise and set identities. A started workout retains its original routine name and reusable intervals separately from session guidance, so a deleted source can still be copied without turning next-session targets into routine intervals.
