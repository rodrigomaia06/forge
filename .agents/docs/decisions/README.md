# Architecture decision records

Create an ADR only when a future contributor would reasonably ask why this was chosen over the
alternatives. Routine refactors, local component choices and implementation details do not get one.

Suggested filename: `0001-short-decision-title.md`.

Suggested structure:

```md
# ADR 0001: Decision title

Status: Accepted
Date: YYYY-MM-DD

## Context

Why a decision is needed.

## Decision

What was chosen.

## Consequences

Important benefits, costs, and constraints.

## Alternatives considered

Only meaningful alternatives.
```

When a decision changes, prefer a new ADR that supersedes the old one instead of rewriting history.
